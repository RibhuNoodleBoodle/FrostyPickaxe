GEMINI ARGON — ARCHITECTURAL SCOPE
FrostyPickaxe / revised 2026-11-05

Goal: a title-specific design for the Xbox 360 Rise of the Tomb Raider on native PC x86-64, using a deliberately selected ReXGlue revision, Vulkan and SDL3-compatible gamepad abstraction. Intel HD 620 performance is a validation gate, not a promised outcome. Evaluate Windows and Linux separately. Android ARM64 is deferred pending PC success.

Sequence:
1. Read all revised evidence and reconcile exact ISO/TU identities. ISO Media ID 0A657B25 differs from TU outer-package Media ID 2427ED57. Plan G1 internal applicability checks before choosing an updated-code workflow. Keep base and updated identities separate; do not force a merge or alter identifiers.
2. Select and justify an immutable SDK/dependency baseline. No SDK is installed here. Previous stable/development labels are historical references, not accepted pins. Verify actual SDL revision and runtime/backend APIs before naming integration details.
3. Map CPU discovery, imports, exceptions, TLS, memory, synchronization, filesystem, streaming, saves, timing, media and guest input responsibilities. Design mount topology from the observed single-disc root and verified update overlay requirements. Do not invent an install disc.
4. Design diagnostic isolation for Xenos shader/fetch/EDRAM/resolve/readback behavior and actual HD 620 device/format capability checks. Choose backend paths conditionally on evidence. Diagnose before prescribing patches or effect compromises.
5. Specify correctness, stability and performance gates and bounded future work packages. Preserve portable guest-memory/platform boundaries for later ARM64 without scheduling Android work.

Acceptance: four coherent design documents specified in the master handoff; each decision has evidence, alternatives, unresolved questions, an owner and pass/fail criteria. Use G0–G5 and EXP-01–EXP-06 from research. No gate is passed by this design session.

Exclusions: implementation files, codegen/build/runtime experiments, asset extraction/decryption/modification, license bypass, uploading game content, commercial PC asset substitution and parallel Android development. The only outputs are architecture documents. Public distribution requires provenance/licensing review of tools, dependencies and generated derivatives. Note that the TU ZIP is currently untracked and unignored; plan private handling before later staging, without changing configuration in this session.
